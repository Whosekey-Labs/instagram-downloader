# 다운로드 구조와 수정 원칙

## 하나의 공통 다운로드 경로

현재 화면, N개, 전체는 대상 게시물 목록을 만드는 방법만 다릅니다. 세 경로 모두 `downloadPosts`에 같은 미디어 조회·파일 저장 어댑터를 전달합니다.

| 계층 | 파일 | 책임 |
| --- | --- | --- |
| UI 및 조립 | `src/inline.js` | 사용자 입력, 범위 선택, 진행 상태 표시, 어댑터 연결 |
| 범위 수집 유스케이스 | `src/lib/post-collection.js` | 중복 제거, 목표 개수/페이지 끝 판단. DOM/네트워크/Chrome에 직접 의존하지 않음 |
| 다운로드 유스케이스 | `src/lib/post-download.js` | 게시물 순차 처리, 조회·저장 의존성 호출, 결과 집계. DOM/네트워크/Chrome에 직접 의존하지 않음 |
| 화면 읽기 어댑터 | `src/lib/page.js` | 화면에 표시된 게시물 링크와 프로필 헤더의 정확한 게시물 수 읽기 |
| 미디어 조회 어댑터 | `src/lib/instagram.js` | 기존에 현재 화면 다운로드가 사용하던 게시물별 미디어 조회 |
| 저장 통신 어댑터 | `src/lib/browser-download.js` | 저장 요청 및 실제 완료 상태 대기 |
| Chrome 저장 구현 | `src/lib/download-service.js` | 다운로드 소유권, Chrome 다운로드 API, 완료 기록/기본값 저장 |

## 이번 오류

N개/전체 처리 앞에 프로필 개수 API 호출을 추가한 것이 원인이었습니다. 현재 화면은 이 단계를 건너뛰어 같은 미디어 다운로드가 가능했습니다. 헤더에 이미 있는 값을 이용하면 되는 상황에서 불필요한 요청을 넣었습니다.

프로필 개수 API 호출과 클라이언트의 count 메서드를 제거했습니다. 헤더에 정확한 수가 없으면 모르는 상태로 처리하며 네트워크 조회로 보충하지 않습니다. N개는 화면 스크롤로 목표 개수에 도달하면 공통 다운로드로 넘깁니다. 전체 개수가 확인되지 않은 채 로딩이 멈추면 모인 항목만 저장하는 선택을 제공합니다.

이번 수정은 잘 동작하는 게시물별 미디어 조회를 제거하는 변경이 아닙니다. 해당 조회와 Chrome 파일 저장은 세 모드가 공통으로 사용합니다. 이미지·영상·묶음 게시물 처리를 유지합니다.

## 변경 원칙

- 범위 옵션을 추가해도 다운로드 함수를 복제하지 않습니다.
- UI와 유스케이스에 별도 API 호출을 추가하지 않습니다.
- 공통 유스케이스는 주입된 입출력 함수만 사용합니다.
- 프로필 조회에서 429를 반환하도록 한 회귀 테스트에서 세 경로가 모두 해당 조회 없이 동작해야 합니다.
- 배포 파일에 프로필 개수 엔드포인트가 포함되면 빌드를 실패시킵니다.
- 미디어 조회에서 실제 429/인증 제한이 발생하면 그대로 중단합니다. 다른 엔드포인트나 세션으로 우회하지 않습니다.
